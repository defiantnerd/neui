## Attribute API

`NEUI_API_ATTRS`. String-keyed bag per widget (`std::unique_ptr<AttrBag>` on `WidgetData`, lazy). API: `set_int`/`get_int(default)`, `set_float`/`get_float(default)`, `set_string`/`get_string`, `has`, `remove`. Type-strict: wrong-kind returns the default. Well-known keys are debug-asserted to match their documented kind at set time via `k_well_known_attrs` (`hosts/shared/attrs.h`); release silently stores the wrong kind so reads keep returning the default. **A new `NEUI_ATTR_*` / `NEUI_PARAM_*` macro needs a matching row in `k_well_known_attrs`.** Session-level: `set_session_int`/`get_session_int`. `NEUI_ATTR_THEME_MODE` is the only session key with behaviour today.

**Well-known keys** (all `neui.attr.<name>`; macros `NEUI_ATTR_*`):

| Key | Type | Applies | Notes |
|---|---|---|---|
| `tristate` | int | CHECKBOX | Implicit on CHECKBOX3. |
| `multiline` | int | MULTILINE | Read-only marker set when a MULTILINE is created. Multi-line is type-determined (NEUI_W_MULTILINE), NOT a live switch - hosts never read this attr, so setting it on an INPUTBOX is inert. |
| `line_wrap` | int bool | MULTILINE | `0`/unset (default) = no wrap (long logical lines clip at the right edge; no horizontal scroll). `1` = soft word-wrap at the content width (word boundaries, char-break for over-long words); explicit `\n` still forces a new row; all nav/selection/scroll operate on the resulting visual rows. xpl host: live (re-flows next paint). Native hosts: use their control's own wrap. |
| `readonly` | int | INPUTBOX, MULTILINE | Gates modifying keys. |
| `password` / `border` / `align_text` | int / int / string | various | Reserved - except `align_text` on SECTION, live. On SECTION: `"none"` hides chip + header band entirely so the body fills the rect; `"left"`/`"center"`/`"right"` selects the chip position. |
| `scroll_mode` | string | SECTION | `"none"` (default) / `"vertical"` / `"horizontal"` / `"both"`. Non-`"none"` clips children to the body rect + scrolls via wheel + scrollbar drag; lazy-allocates a `SectionScrollState`. Wheel scrolling runs the same smooth kinetics as GRID (`scroll_kinetics.h`, per-axis `kin_v`/`kin_h`): pixel-precise trackpad + inertial momentum + elastic rubber-band + 60 Hz spring-back on macOS; synthetic precise notches + rubber-band on Win32; classic wheels hard-clamp at `SECTION_WHEEL_LINE_PX` (40 px) per line. xpl: platform layer intercepts the wheel for the nearest scrolling-section ancestor and gives widgets below it first refusal via a bounded `dispatch_wheel_event(hit, ev, stop_before)` bubble. Win32 native: `painted_msg_section_w32` consumes `WM_MOUSEWHEEL` / `WM_MOUSEHWHEEL` on the section's own HWND; the SECTION HWND gains `WS_CLIPCHILDREN` so child HWNDs clip to its bounds, and `parent_scroll_offset_w32` subtracts the section's scroll from child HWND positions at `widget_set_pos` / `cascade_dpi` time. macOS native: `NEUINativePaintedView::sectionScrollWheel:` consumes the wheel (NSResponder default forwards through child NSViews that don't consume), and `section_reposition_children_macos` shuffles direct subviews' `frame.origin` on every scroll commit. macOS native (like Win32's inner body HWND) parents a scrolling section's children to an inner `NEUISectionBodyView` - a transparent, layer-clipped subview at the body rect - via `section_child_container_macos`, so children clip to the body + sit below the chip band; the section's own paint fills the body bg underneath (the body view does NOT self-fill: an opaque `NSRectFill` broke sibling painted-view rendering), and `wantsLayer`+`masksToBounds` supplies the clip NSView doesn't do by default. **Every** macOS SECTION (scrolling or not) also sets `wantsLayer`+`masksToBounds` on its own painted view so children always clip to the section rect, matching win32's HWND-parenting clip - without it a non-scrolling section (or one switched to `scroll_mode="none"`) lets overflowing children spill outside the section. **The inner body container (`NEUISectionBodyView` / win32 `body_hwnd`) is created the first time a section becomes scrollable and KEPT for the section's lifetime - including after switching back to `"none"` - so children stay body-local (below the chip band) + clipped in every mode; destroying it on a flip-to-`"none"` dropped children to section-local coords and overpainted the chip.** A section created `"none"` and never scrolled has no body container (children parent to the section view directly, section-local). Switching `scroll_mode` resets the scroll offset to 0,0. All hosts route the math through `section_scroll_wheel_kinetic` / `section_scroll_bounce_step` (`widget_section_scroll.h`), with the STEPPED branch going through `section_scroll_step_px` instead. `NEUI_ATTR_SCROLL_KINETICS` (see `scroll_kinetics` below) selects the feel - PLATFORM defaults to smooth on macOS and stepped on Win32 / null. Live. |
| `content_width` / `content_height` | int (logical px) | SECTION | Override the auto-bounding content extent (`max(child.x + child.width)` / `max(child.y + child.height)`). 0/unset = auto. Live. |
| `tab_stop` | int | focusable | Replaces deprecated `widgets->set_tab_stop`. |
| `input_transparent` | int bool | any widget | `1` = paint normally (full opacity) but never claim a hit-test, so the pointer falls through to the widget/parent beneath. Distinct from `enabled=false` (also click-through but force-dimmed to 50%) and `emit_events` (governs emission). xpl: skipped in the `widget_at` walk, read live. win32 native: child created `WS_EX_TRANSPARENT`. macOS native: `hitTest:` returns nil. Use for decorative overlays / rulers / HUDs. |
| `overlay` | int bool | CUSTOMDRAW | `1` = transparent overlay: composite over the sibling widgets beneath with per-pixel alpha (no background clear; unpainted pixels stay transparent). xpl: a no-op (CUSTOMDRAW already composites in the single-surface walk). win32 native: child created `WS_EX_NOREDIRECTIONBITMAP` and rendered through a DirectComposition visual + composition swap chain (premultiplied alpha) so DWM composites it GPU-side over the siblings - suitable for high-frame-rate overlays (meters / spectrum). Read at `widget_show` (window style + render path fixed at creation). macOS native: the CUSTOMDRAW's painted NSView is already non-opaque, so the overlay clears transparent (instead of `panel_bg`) and AppKit composites it over the backdrop sibling; read live each `drawRect:`. Pair with `input_transparent` for click-through. |
| `min_width` / `min_height` / `max_width` / `max_height` | int (logical px) | APPWINDOW | Drives `WM_GETMINMAXINFO` / `NSWindow.min/maxSize`. `max < min` = no maximum. |
| `icon_path` | string | APPWINDOW | `.ico` / `.png` / `.bmp` / `.jpg`. Live. |
| `modal` | int | DIALOG | `1`/unset → owner disabled AND `widgets->show` blocks the calling thread in a nested OS event pump until the dialog is destroyed. Read once at `widget_show`. |
| `background` | int ARGB | KNOB, IMAGE, painted widgets, frame on xpl | Honoured unconditionally (independent of follow-system-theme). |
| `follow_system_theme` | int bool | APPWINDOW, PLUGWINDOW, DIALOG | `1` = DWM dark + dark HMENU + theme-aware `WM_CTLCOLOR*` + invalidate on theme flip; `0`/unset = OS-default chrome, no auto-invalidate. Default off. |
| `ui_scale` | float | APPWINDOW, PLUGWINDOW, DIALOG | **xpl host only.** User UI zoom on top of the monitor's DPI scale: `1.0`/unset = none, `1.5` = 150 %. Clamped to `[NEUI_UI_SCALE_MIN, NEUI_UI_SCALE_MAX]` (0.25 .. 8.0). The client's coordinate system is unchanged - widget `x/y/width/height`, `get_client_rect` and mouse coordinates stay logical px at 96 DPI at every zoom, so a layout written once is correct at every zoom. Implemented as one CTM `scale` wrapping the whole frame paint (widget walk + all overlays) in `Session::paint_frame`, a divide in each platform's native→logical input conversion, and a multiply in each logical→native window-size conversion. `measure_text` is transform-independent and the font caches are DPI-free, so no text metric or cache work is involved. Live: re-sizes the native window so the logical client area is preserved, repaints, and fires `NEUI_EVENT_METRICS_CHANGED` carrying the new scale. Native win32 / macOS hosts ignore it (their children are real OS controls sized by the OS). |
| `paint_device_pixels` | int bool | CUSTOMDRAW | **xpl host only.** `0`/unset = the `WIDGET_PAINT` callback draws in logical px and the framework scales the result (default). `1` = the callback receives DEVICE pixels: `neui_event_paint_t` `width`/`height` arrive multiplied by the zoom and the zoom transform is not applied under the callback, so one unit is one device-side pixel. For content that must be pixel-exact - meters, spectrum analysers, waveform / scope views. Position, size and clip in the surrounding layout stay logical; only the space inside the callback changes. Mouse coordinates delivered to the widget stay LOGICAL either way. Read `neui_event_paint_t::scale` (available in both modes, on every host) for the device scale. |
| `rotation` | float (rad) | IMAGE | Around dest centre. Positive = clockwise (Y-down). Live. |
| `polarity` | string | KNOB | `"min"` (default) / `"center"` / `"max"`. Anchor end of fill arc. |
| `steps` | int | SLIDER, KNOB | `>=2` snaps to N positions on `[0..1]` + draws ticks; `<2` continuous. Also snaps programmatic `set_float(NEUI_PARAM_VALUE)`. |
| `orientation` | string | SLIDER | `"horizontal"` (default) / `"vertical"`. Read at `widget_show`. |
| `value_text` | string | KNOB | Overlay text below the disc. Read each paint. |
| `knob_mode` | int | KNOB | `NEUI_KNOB_MODE_ROTATIONAL=0` (default) / `_VERTICAL=1` / `_HORIZONTAL=2`. Cached at mouse-down. |
| `combo_max_visible` | int | COMBOBOX | Max item rows shown in the drop list before it scrolls. Default 10; `<1` clamps to 1. The drop list grows to `min(item_count, this)`. xpl + win32 native (`CB_SETMINVISIBLE` + HWND height bump); macOS native ignores it (NSPopUpButton auto-sizes). Live. |
| `combo_drop_width` | int (px) | COMBOBOX | Explicit drop-list width override. 0/unset = auto (widest entry + padding + scrollbar column on overflow). Never narrower than the collapsed bar. xpl + win32 native (`CB_SETDROPPEDWIDTH`); macOS native ignores it. Live. |
| `font_family` / `font_size` / `font_weight` | string / float px / int | text-bearing | Empty/unset = host default. Weight CSS 100..900 (400 Normal, 700 Bold). Honoured by d2d + cg backends + native controls (win32 `HFONT`, macOS `NSFont`; unknown families fall back); null ignores. Italic not exposed. Live. |
| `theme_mode` | int session-level | session | AUTO (0) follows OS; LIGHT (1) / DARK (2) force the palette. Accent stays live. |
| `grid.row_height` | int (px) | GRID | Body row height. Default 22. |
| `grid.header_height` | int (px) | GRID | Sticky header band height. Default 24. |
| `grid.focus_row_color` | int ARGB | GRID | Focus-row band colour. 0/unset = accent @ 0x33 alpha. |
| `grid.show_focus_row` | int bool | GRID | Paint focus-row highlight. Default 1. |
| `grid.column_min_width_default` | int (px) | GRID | Default per-column min width. Default 24. |
| `grid.cell_focus` | int bool | GRID | 0 = row-focus (default); 1 = cell (row,col) cursor. Live. |
| `grid.lines_color` | int ARGB | GRID | Colour of the 1 px grid lines between cells (per-row bottom + per-column right edge, inside the body clip). 0/unset = no grid lines. Live. |
| `grid.row_bg_a` | int ARGB | GRID | Row background painted behind cell text (under the focus band). Even visible rows use A; with `row_bg_b` set this gives a zebra stripe, else every row uses A. 0/unset = body bg shows through. Live. |
| `grid.row_bg_b` | int ARGB | GRID | Alternating row background for odd visible rows. 0/unset = odd rows fall back to A (or body bg if A unset). Live. |
| `grid.header_bg_color` | int ARGB | GRID | Fill colour for the sticky header band. 0/unset = theme `panel_bg` role. Translucent alpha tints over the body bg. Live. |
| `grid.scroll_mode` | int | GRID | Wheel kinetics. `NEUI_GRID_SCROLL_PLATFORM=0` (default - macOS = smooth, Win32/null = stepped), `_STEPPED=1` (row-quantized, hard-clamp), `_SMOOTH=2` (pixel-precise + rubber-band + 60 Hz spring-back). Live. Superseded by `scroll_kinetics` when both are set; kept as a GRID-only back-compat alias. |
| `scroll_kinetics` | int | SECTION, GRID | Generic wheel-kinetics selector. `NEUI_SCROLL_KINETICS_PLATFORM=0` (default - macOS = smooth, Win32/null = stepped), `_STEPPED=1` (hard-clamp, no rubber-band, no momentum), `_SMOOTH=2` (rubber-band + 60 Hz spring-back). Numeric values match `NEUI_GRID_SCROLL_*`. On SECTION, STEPPED resyncs the kinetics integrator (via `section_scroll_step_px`) so a later flip to SMOOTH starts cleanly. On GRID this attr takes precedence over `grid.scroll_mode` when both are set. Live. |
| `nav_count` / `nav_index` / `nav_page` / `nav_wrap` | int / int / int / int bool | POPUPSURFACE | **xpl host only.** A client-DECLARED item list, so the host can run arrow / Home / End / PageUp / PageDown / Enter navigation over content it does not own. A popup surface is normally painted by the client, and inside a `NEUI_W_CUSTOMDRAW` the host has no rows to walk - these say how many items there are (`nav_count`, 0/unset = **no host navigation at all**, the default) and which is current (`nav_index`, `-1` = none, so a freshly opened menu highlights nothing until the first arrow). The client keeps painting from the index; the host only does the arithmetic. `nav_page` is the PageUp / PageDown step (0/unset = 10) and **paging always clamps**, even with wrap on. `nav_wrap` (default 1) is the menu convention - Up from the first goes to the last; set 0 to clamp, which is what a scrolling browser list usually wants. Navigation runs **only** on the deepest open surface, **only** while focus is outside it (a focused widget inside the popup keeps its own arrows - a text field must), and **only after the client's own handler declined the key**: returning `true` from `onevent` for a `NEUI_EVENT_KEYDOWN` takes that keystroke away from the host entirely, so the override is per key rather than per popup. A host move writes `nav_index` and reports `NEUI_EVENT_ATTR_CHANGED { surface, nav_index, value }`; `Enter` on a real selection fires `NEUI_EVENT_ITEM_SELECTED { surface, index }`. A **client**-written index fires nothing (or a client syncing the index on hover would loop), and a clamped arrow at the end of a non-wrapping list fires nothing either, so a held key cannot spam the client. `nav_count` is live: a filtered list may re-declare it per keystroke, and an index left past the new end is treated as "none" rather than walked from. Arithmetic in `hosts/shared/popup_nav.h`, Tier-1 tested (`tests/test_popup_nav.cpp`). Live. |
| `cursor` | string | any **hit-testable** widget | Mouse-cursor shape while the pointer is over this widget. **xpl host only** - the native hosts leave cursors to their OS controls, so a client that wants this selects `neui.host.crossplatform` (as for `NEUI_API_TIMER` / `_EMBED`). **Applies where the pointer can hover**, i.e. a widget that takes part in hit-testing (`emit_events`: BUTTON, INPUTBOX, CUSTOMDRAW, GRID, KNOB, a scrolling SECTION, ...). On a widget that never hit-tests - LABEL, IMAGE, a non-scrolling SECTION's bare background, anything `input_transparent` - it is **inert**, because the pointer is logically interacting with whatever lies beneath, and that widget's cursor wins. **Inherits**: unset (or `"default"` / `"inherit"`) walks up to the nearest ancestor that sets one, falling back to the OS arrow at the root - so `"ibeam"` on a SECTION covers the interactive children inside it (not its bare background, per the above). Canonical names: `default`, `arrow`, `ibeam`, `crosshair`, `hand`, `open-hand`, `closed-hand`, `ew-resize`, `ns-resize`, `nesw-resize`, `nwse-resize`, `move`, `wait`, `progress`, `help`, `not-allowed`, `none`. CSS aliases accepted (`inherit`, `text`, `cross`, `pointer`, `grab`, `grabbing`, `col-resize`, `row-resize`, the eight `n/s/e/w/ne/nw/se/sw-resize` edge names, `all-scroll`, `busy`, `no-drop`, `forbidden`, `hidden`), and `_` works wherever `-` does. An **unrecognised value means inherit, not arrow**, so a typo can't silently override an ancestor. Stored **canonicalised**: `get_string` reads back the canonical name, not the alias written (`"pointer"` -> `"hand"`), and an unknown name reads back as `"default"` so a client can see it wasn't understood. Live - a write under the pointer applies at once, and so does `remove`. **A drag owns the cursor**: while a widget is the press target its shape persists until release even with the pointer outside its rect, matching platform convention (a splitter keeps its resize arrow when you overshoot it) - the press target is where every mouse event is still going. Resolution + the parse live in portable code (`Session::resolve_cursor_for`, `hosts/shared/cursor_kind.h`, Tier-1 tested in `tests/test_cursor_kind.cpp`); the platform layer only ever receives a concrete shape. Internal *positional* feedback outranks it for the pixels it covers - the GRID header column-resize band shows `ew-resize` and hands the shape back to this attr elsewhere. Not every shape is native everywhere (macOS diagonals are public only from macOS 15; `move`/`help` have no public equivalent; `wait`/`progress` are unhonourable on macOS by design; win32 has no separate open/closed hand) - see `docs/deferred-issues.md`. |

Namespace `neui.attr.*` reserved; clients use their own. Host-specific reserved: `neui.win32.*`, `neui.macos.*`, `neui.linux.*`. Unknown keys stored but inert.

## Scroll API

`NEUI_API_SCROLL` (`include/neui/d/scroll.h`). Programmatic control over a scrolling SECTION. Methods: `set_scroll(sess, section, x, y)` (clamps to legal range, cancels in-flight bounce by resyncing the kinetics integrator, fires `SCROLL_CHANGED`), `get_scroll(sess, section, out_x, out_y)`, and `ensure_visible(sess, widget)` (walks the widget's parent chain to the nearest scrolling SECTION ancestor and minimum-motion-scrolls so the widget is fully inside the body rect; already-visible widgets are no-ops; widgets larger than the body align to the top-left). All three live on every host through a shared `Session::ensure_widget_visible` (xpl + win32 native) / `find_scrolling_section_ancestor_macos` (macOS native) plus the per-host `section_external_commit_*` helper. `compute_ensure_visible` math (`hosts/shared/widget_section_scroll.h`) is host-neutral. `NEUI_EVENT_SCROLL_CHANGED { widget, scroll_x, scroll_y }` fires whenever the committed offset of a scrolling SECTION changes (wheel, scrollbar drag, spring-back tick, programmatic set); SectionScrollState carries `last_notified_x/y` so a tick that rounds to the same px stays silent.

**Auto-scroll on focus change**: `Session::set_focus` (xpl) + `WM_SETFOCUS` (win32 native) call `ensure_widget_visible` on the newly-focused widget so Tab traversal into an off-screen child auto-brings it into view. Not wired on macOS native today - the per-widget focus event is Tier B deferred, so AppKit's key view loop handles Tab without notifying the framework. The public `ensure_visible` API works on all three hosts.
