## Deferred Issues

- **Deduplication non-goals** (a 2026-06 dedup campaign consolidated the asset managers, draw_asset thunks, DnD dispatch/seam/helpers, macOS window helpers and backend colour/alpha math into `hosts/shared/` + `backends/shared/`; these were deliberately left per-host/per-backend - do not "unify" them): DnD hit-test walkers (xpl virtual `hit_test` vs native on-the-fly coord accumulation - different contracts), the two macOS window delegates' close logic (native drives sheet `endSheet:` in `windowShouldClose:`, xpl tears down the render ctx in `windowWillClose:`), backend transform/clip stacks (CG `SaveGState` saves clip+CTM atomically), font-cache containers (D2D struct-keyed wstring vs CG string key), the null backend's explicit no-op vtable (documents the interface), example scaffolding.
- **KNOB not a keyboard tab-stop on macOS** - the NSView refuses first responder. Needs focusable + arrow-key value handling.
- **macOS Tab participation follows the system Full-Keyboard-Access setting** - traversal *order* matches win32, but *which* control types Tab visits beyond text fields / lists is OS policy. Hand-roll Tab for fully deterministic traversal.
- **Tier B focus parity** (xpl proxy HWND per widget for UIAutomation; NSAccessibility seam on macOS).
- **Image clipboard / DnD** - `text/plain`, `text/html`, `text/uri-list`, arbitrary MIMEs, and `image/png` (`NEUI_MIME_PNG`) are wired on every host and platform. Win32: `image/png` is published as `CF_DIBV5` (PNG bytes decoded via WIC into a `BITMAPV5HEADER` + 32bpp BGRA pixel block) alongside the registered MIME, so Paint / Explorer / Outlook see the image; reverse path re-encodes a `CF_DIBV5` / `CF_DIB` drop back to `image/png` bytes via WIC. macOS: `image/png` stamps `NSPasteboardTypePNG` (same bytes - PNG is the native macOS bitmap format); iOS: `public.png`. Linux (X11): the MIME is the target atom itself, as GTK / Qt offer images, so no conversion. Open on Linux: XDND has no INCR - `xdnd_read_selection` refuses a chunked (INCR) drop, which large payloads from other apps use, and the drag-source serves each format in one property - so large payloads move by clipboard (INCR both ways) only. `image/tiff` not yet wired (the converter helpers live in `hosts/shared/win32/clipboard_format_png_win32.h`; TIFF would follow the same shape).
- **DnD drag-source extensions** - drag-source API, the `DRAG_SOURCE` behavior-asset handler kind, the custom drag-preview image (`begin_drag_with_preview`; `NSImage` / `IDragSourceHelper`), per-drag result feedback (`DRAG_SOURCE` `result_attr` prop - runtime writes the negotiated `NEUI_DND_ACTION_*` as int + fires `ATTR_CHANGED` + invalidate after `begin_drag` returns), and the generic lazy-provider callback (`clipboard->item_set_format_callback` - bytes produced on demand by a `neui_data_provider_t`; Win32 `DataObjectImpl::GetData` and macOS `NSPasteboardItemDataProvider` defer encoding for arbitrary MIMEs until the receiver actually requests them; built-in MIMEs and clipboard write materialise eagerly at snapshot/write time) all ship on all three hosts; deferred follow-ups: file-promise interop (`CFSTR_FILECONTENTS` + `CFSTR_FILEDESCRIPTOR` for Explorer / Outlook; `NSFilePromiseProvider` for Finder - separate from the generic provider in that the OS wants a path / IStream specifically), true deferred-render on clipboard write via `WM_RENDERFORMAT` (Win32) and `NSPasteboardItem` promise-of-promise (macOS).
- **macOS clipboard change-notification** - `NSPasteboard.changeCount` polling is not wired; the API has no `onchange` event anyway, clients poll on demand.
- **Multi-session palette** - `active_palette_override_ptr` is process-wide (last-set-wins).
- **SVG filter primitives** beyond `feFlood` / `feColorMatrix` / `feOffset` / `feGaussianBlur` / `feComposite` / `feBlend` / `feMerge`: `feMorphology` (the blocker for an outline/stroke convenience), `feComponentTransfer`, `feTile`, `feImage`, `feTurbulence`, `feDisplacementMap`, `feConvolveMatrix`, lighting. Also: linearRGB colour-interpolation (sRGB only today, per the designer's `color-interpolation-filters="sRGB"`), `feComposite operator="out"` semantics for *semi-transparent* (vs opaque) shapes, and an SVG `<filter>` *parser* feeding the graph (the engine is parser-agnostic; parser location - in-core vs helper lib - is an open decision). Filters are CPU/bake-time on a SURFACE by design; per-frame GPU filtering would be a separate backend-native layer.
- **Compound layer kinds** beyond `text` / `asset` / `rect` / `path` / `qr` / `group` / `arc` / `shader`: template format specs (`{key:.2f}`); SVG-mini string form for `set_path`. (Cubic/quadratic bezier on PATH now ship - `NEUI_PATH_CMD_CUBIC_TO`/`_QUAD_TO`, `neui_path_cmd_t.args` widened to `[6]`, **full rebuild required** like the `AssetEntry` note. The `group` container layer now ships too - `NEUI_COMPOUND_LAYER_GROUP` + `add_child_layer`, see the Compound drawables section.)
- **Behavior detent / plateau modifier** - per-handler "sticky values" that resist near specific points (distinct from `steps`); behavior pen pressure / tilt (pen surfaces as mouse); `cursor` prop no-op; wheel modifier-fine needs a `neui_event_wheel_t` payload extension.
- **GRID sort follow-ups** - STRING kind is byte-level `strcmp` (locale-aware compare deferred); no per-column custom comparator callback (clients pre-format or pick STRING / INT / FLOAT / NATURAL); no built-in DATE / TIME kind.
- **Drag input is not coalesced per frame (Windows)** - since D2D presents without vsync, the UI thread no longer sits in `Present`, so Windows stops coalescing a 1000 Hz mouse into ~60 moves a second and every `WM_MOUSEMOVE` of a drag runs the value update (behavior / knob handler, `VALUE_CHANGED`, the client's handlers, invalidation): ~60 µs a move in a Debug build, so a drag costs more CPU than with vsync at the same paint rate (xpl 17.7% vs 11.0%). Applying the latest pointer position once per paint or tick would cut it.
- **Text antialiasing differs between a partial and a full frame (D2D)** - text inside a partial frame's damage (drawn under the pushed clip / layer) and the same text in a full frame differ by up to ~150/255 per channel on glyph edges (ClearType vs grayscale?), so a region repainted partially can look slightly different from a full repaint. Pre-existing, found while verifying present pacing.
- **Native win32: a CPU-heavy drag costs a neighbouring animation frames** - the native host paces each painted HWND on its own (each has its own swap chain), so while a CPU-shaded knob is dragged, its re-shades plus the input keep the queue busy and the animated panels' `WM_TIMER` ticks (lowest priority) slip: 47-54 fps instead of 60 (xpl, one chain for the whole frame, holds 60). Far better than with vsync (~20), but pacing all of a frame's painted HWNDs together would remove it.
- **Occluded windows keep painting (D2D)** - a window fully covered by another (not minimised, not hidden) still gets its paints, so an animation in it keeps its full cost. Ticks could be skipped while `Present1` reports `DXGI_STATUS_OCCLUDED`.
- **Scaled bitmaps on the macOS xpl host can change look after the first frame** - AppKit draws a layer-backed view's recorded CG calls with CoreGraphics in software on a full redraw (a 2x upscale samples about 1/8 texel from the texel centres, a little sharper) but through Core Animation's GPU path (`CA::OGL::Mosaic`, exact bilinear) on a partial redraw (`setNeedsDisplayInRect:`) of a large view, and keeps that path afterwards. The xpl host draws a window into one view with partial repaint, so a bitmap drawn scaled (an IMAGE widget fitted to a different size, an ASSET layer, a shader layer at `resolution` above 1, under a rotation or too large for neui to scale up) can differ by up to ~48/255 on edges between the first frame and later ones, and from the native host (small per-widget views, always full redraws). Bitmaps drawn 1:1 are unaffected, and shader layers below `resolution` 1 are scaled by neui itself (`nsl::upscale`). A plain Objective-C++ AppKit app shows the same; a Swift one did not. Fix if it matters: scale in software before drawing, as the shader path does.
- **Web host limits** (`docs/host-web.md`): no drag out of the page (browsers start drags only from a native `dragstart`); popups and combo lists clip at their canvas, which matters for small embedded canvases; no runtime fetch of image URLs (bundle them or use `NEUI_API_RESOURCE_CLIENT`); no WebGL2 shader path (shaders run on the CPU executor, SIMD128); no accessibility mirror (canvas UIs are invisible to screen readers); one browser window per app. Not verified for lack of devices: Safari on macOS / iPadOS, a real IME, Android / iOS virtual keyboards, real touch screens, desktop drags from Explorer / Finder.
- **Popup menu keys on iOS (xpl host)** - win32, macOS, Linux, the web and the LVGL host route Esc / Enter / arrows to an open `popup_menu` (`Session::handle_popup_key`); on the iOS xpl platform hardware-keyboard keys do not reach an open popup.
- **Linux reduced motion** - the animation clock does not read a reduced-motion setting on Linux (`platform_reduced_motion` returns false); the XDG desktop portal carries one only on recent versions.
- **LVGL host gaps** - not listed individually here: that host is **experimental** and opt-in, so its stubs (clipboard / DnD / IME / native menubar / message boxes / off-screen surfaces / font registration / DPI scaling) are a scope boundary rather than deferred work on a shipped feature. The full list, and why the remaining work waits for real hardware, is in `docs/host-lvgl.md`.
