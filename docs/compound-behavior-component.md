## Compound drawables

A **compound** is `NEUI_ASSET_KIND_COMPOUND` - a mutable, declarative shape attachable to a CUSTOMDRAW widget. Owns a slot-reused layer stack; each layer is `text`, `asset`, `rect`, `path`, `qr`, `group`, or `arc`, positioned by a 9-point anchor pair (parent + self) + `(offset_x, offset_y)` + `(width, height)` with `NEUI_COMPOUND_FILL = -1` per axis to span; signed-int `z` interleaves with the widget's children (`z<0` below, `z>=0` above). When attached, `WIDGET_PAINT` is suppressed.

**Group layers** (`NEUI_COMPOUND_LAYER_GROUP`, built via the vtable-appended `compound->add_child_layer(parent, kind, z)`): a container that establishes a transform+clip scope at its own (bindable) layer rect and holds a sub-list of child layers. The model stays a flat slot table - each `CompoundLayer` carries a `parent` slot (0 = top-level), so every `set_*` / `bind` / `remove_layer` call works on a child handle unchanged; `compound_remove_layer` on a group tears down its whole subtree. Children anchor/size against the GROUP rect (not the widget) and clip to it. A group is **one** layer at the widget level: its own `z` alone decides below/above the widget's real children; child `z` orders layers only *within* the group and never interleaves with the widget's children (`paint_compound_pass` walks only `parent==0` layers; the `GROUP` case in `paint_compound_layer` recurses over `compound_sorted_children`, depth-capped at `k_compound_max_group_depth`). Child layers read the **same widget AttrBag** (templates + numeric/asset bindings) at the same priority as top-level layers - no separate data plane. `alpha` / `show_when` on the group apply to the whole subtree. Groups nest. Declarative form: a `{"kind":"group", ..., "layers":[ ... ]}` object (recursive build + serialize in `component_loader.h`).

**API** (`include/neui/d/compound.h`, `NEUI_API_COMPOUND`): `add_layer(kind, z)`, `remove_layer`/`clear`/`set_z`, `set_anchor`, typed `set_int`/`set_float`/`set_string`(templates)/`set_asset`, numeric `bind(prop, attr_key, scale, offset)`, `bind_asset(prop, attr_key)`, `unbind`, `set_path(cmds, count)` (PATH layers only), `set_gradient(grad)` (RECT / PATH layers - sets/clears a linear/radial gradient FILL overriding `fill_color`; stroke + corner_radius + path geometry still apply; NULL or <2 stops clears. Geometry is NORMALISED to the layer rect: start/end/focal x,y are [0,1] fractions, `radius` a fraction of the larger dim - `widget_paint_compound.h::resolve_layer_gradient` maps it to absolute px per paint, origin = layer rect for RECT / (0,0) for the translate-framed PATH; stops are snapshotted into `CompoundLayer::GradientFill` like `set_path` copies cmds; routes to the backend `fill_rect_gradient`/`fill_path_gradient`). Props - **text**: `text` (template), `size`, `color` (optional, → `ColorRole::text_primary`), `align_x`/`align_y`; **asset**: `asset`, `rotation`, `tint` (ARGB multiplicative; 0xFFFFFFFF passthrough short-circuits the backend's tint primitive entirely so untinted draws cost nothing extra; any other value runs the backend's native multiplicative-tint path - `CLSID_D2D1Tint` effect on Windows via `ID2D1DeviceContext::DrawImage`, transparency layer + `CGContextClipToMask` + `kCGBlendModeMultiply` on macOS (RGB multiplied at full strength inside the isolated layer, then composited at tint-alpha x alpha-stack so a translucent tint bleeds background like D2D; deeply translucent tints render marginally darker than D2D's unclamped premul multiply, identical for opaque `0xFFrrggbb`) - reusing the single per-`(asset, ctx)` upload regardless of how many tints reference it, so animating the tint is free; `tint == 0` short-circuits the layer entirely); **rect**: `fill_color`, `stroke_color`, `stroke_width`, `corner_radius` (clamped to `min(w,h)/2`; sharp falls back to `fill_rect`/`draw_rect`, rounded builds a single 4-arc path that is fill+stroke'd in one go) plus an **opt-in value-driven fill** (the linear bar / level meter): `value` ([0..1] painted **fraction** of the rect along the fill axis, default `1` = full so an unbound rect is unchanged, almost always BOUND - `bind("value","neui.param.value",1,0)` - clamped at paint), `orientation` (`0` horizontal default / `1` vertical, or string `"horizontal"`/`"vertical"`), `polarity` (fill anchor, same enum as the arc / KNOB: `0` min/origin edge default, `1` center/bipolar, `2` max/far edge). The fill draws into the value-derived sub-rect (honouring `corner_radius`); the **stroke always outlines the FULL rect** as a track, and a gradient fill stays mapped to the full rect (a fixed scale revealed by the fill). At `value==1` the sub-rect equals the full rect, so paint is byte-for-byte the static behaviour; **path**: `fill_color`, `stroke_color`, `stroke_width` (shared with rect) plus `set_path(neui_path_cmd_t[], count)` to assign geometry - command kinds `MOVE_TO`/`LINE_TO`/`ARC`/`CUBIC_TO`/`QUAD_TO`/`CLOSE` mapping 1:1 to the backend path API; coords are layer-local (painter pushes a transform to the layer rect before replay). `neui_path_cmd_t.args` is **six floats** (a cubic needs two control points + end); the component-JSON path ops are `m`/`l`/`a`/`c`/`q`/`z`. PATH also supports **value-driven arc-length stroke trim** (the universal "render `value` fraction of me" - covers line, polyline, rect outline, rounded rect, any path; the ARC layer is the circular special case): `value` ([0..1] trimmed **fraction** of the path's total arc length to stroke, default `1` = whole path so an unbound path is unchanged byte-for-byte, normally BOUND, clamped at paint), `polarity` (trim anchor, same min/center/max enum as the arc: `0` from start default, `1` grows out from the middle/bipolar, `2` from the end). Trim is a **geometry op on the STROKE only** - fills always use the whole path (a partial fill of an arbitrary path has no canonical meaning). Implemented backend-agnostically in `widget_paint_compound.h::trim_path_commands`: flatten cmds to a polyline (lines exact, curves/arcs sampled), measure cumulative arc length, emit the `[a,b]·L` sub-path as `MOVE_TO`/`LINE_TO` (boundary segments split by lerp), then stroke that. `value<=0` strokes nothing (the fill track still shows); **qr**: `text` (template, default `"{value}"`; overridden when the widget's AttrBag carries a non-empty `NEUI_ATTR_QRCODE` string, which is then encoded verbatim), `fill_color` (dark-module ARGB, 0 = theme `text_primary`), `background` (ARGB behind modules + quiet zone, 0 = transparent), `ecc` (`neui_qr_ecc_t` 0=LOW..3=HIGH, default MEDIUM), `quiet_zone` (modules, default 4, clamped [0,16]) - the symbol is generated by the vendored `qrcodegen` (Project Nayuki, `third_party/qrcode/`), rasterised once into an internally-held BGRA8 bitmap (one integer-sized module block per QR module) and blitted at native resolution (centred + letterboxed to stay square + crisp). For crispness at fractional DPI (e.g. 150%) the draw origin is **pixel-snapped to the device grid** (`std::lround(coord*scale)/scale`) and the d2d backend draws native-size (1:1 device-px) bitmaps with **nearest-neighbor** interpolation rather than linear (see the `draw_bitmap` note in Backends) - without both, the symbol's module edges bilinear-smear into uneven-width gray lines. The bitmap cache is **per resolved value, not per layer**: a shared compound layer keeps a small generation-keyed cache (`CompoundLayer::QrSymbol`, key = text + target px size + colours + ecc + quiet, FIFO-capped at `k_qr_cache_max = 16`), so N widgets sharing one QR layer each render their own (different) code rather than thrashing one held bitmap. Encode failure (text too long) / empty text draws nothing. Per-`(ctx)` GPU uploads live on each `QrSymbol` and are freed by `AssetStore::release_context`/`clear` (via `compound_release_ctx_bitmaps`); **arc** (value-driven ring / pie - generalises the KNOB active-fill arc to a designer-authorable, value-bound layer): `value` ([0..1] swept **fraction**, almost always BOUND - `bind("value","neui.param.value",1,0)` - so a knob/meter value drives the sweep live; clamped at paint), `begin_angle`/`end_angle` (degrees of the full range; `0° = 12 o'clock`, +cw on screen; defaults `-135`/`135` = the knob's 270° sweep; bindable), `direction` (`0` cw default / `1` ccw - which way the begin→end range travels), `polarity` (anchor end of the fill, reusing the KNOB `NEUI_ATTR_POLARITY` values: `0` min/from-begin default, `1` center/from-midpoint for bipolar, `2` max/from-end), `fill_color` (filled wedge / pie, centre→arc), `stroke_color`/`stroke_width`/`stroke_cap` (stroked ring along the arc). The arc is inscribed in the layer rect - `rx = width/2`, `ry = height/2`, so it is **elliptical** when `width != height`; the ring insets by `stroke_width/2` to stay inside the rect. Rendered as cubic-Bézier segments (`widget_paint_compound.h::append_elliptical_arc`, ≤90°/segment, `k = 4/3·tan(Δ/4)`) through the painter's `cubic_to`, so it needs no backend changes and is cheap per-frame vector paint (never baked). Set `stroke_*` for a ring, `fill_color` for a pie, or both; the JSON layer is `{"kind":"arc", ...}` and `value` is normally bound (the static prop round-trips when set); **all**: `offset_x`/`offset_y`/`width`/`height`/`alpha`/`show_when`.

**State-filtered layers** (`NEUI_PROP_SHOW_WHEN`, `set_int`): `0` (default) = always visible; otherwise an AND filter across four axes (enabled, hovered, pressed, selected), each with a positive bit (`NEUI_LAYER_STATE_ENABLED`/`_HOVERED`/`_PRESSED`/`_SELECTED`) and a negated `_NOT_*`; rule `(show_when & ~current_state) == 0` (current_state carries one bit per axis each paint). The framework invalidates on transitions only when the compound `has_state_filters`; per-host wiring populates `wd.hovered`/`wd.pressed`, while the **selected** axis is read at paint time from the widget's `NEUI_ATTR_SELECTED` attribute (client- or behavior-driven, `0`/`1`) - so `set_int(NEUI_ATTR_SELECTED, 1)` both repaints and flips the axis. JSON `show_when` tokens: `"enabled"`, `"hovered"`, `"pressed"`, `"selected"`, each negatable with a leading `!`.

**Data plane = the widget's `AttrBag`** (no parallel store on the compound). Text layer `"{label}: {value}"` resolves keys against attrs at paint time; `bind(layer, "rotation", "value", 2π, 0)` reads `value` as float (`attr_as_float`), computes `scale*x + offset` (float→int targets round). One compound backs many widgets - shape shared, attrbag per-widget. Template `{key}` substitution, `{{`/`}}` literal braces, malformed/missing → empty/pass-through, pre-parsed at `set_string` (`{key:.2f}` reserved). `attrs->set_*` on a widget with a compound invalidates it; compound mutations invalidate every CUSTOMDRAW whose `compound_asset` matches.

**Storage + paint**: `AssetEntry` / `W32AssetEntry` / `MacOSAssetEntry` carry a `std::unique_ptr<CompoundAsset>`. Layer table + parse + geometry + binding eval in `compound.h`; paint in `widget_paint_compound.h::paint_compound_below` / `_above`. All hosts call `_below` before child descent, `_above` after - xpl wires `_above` through `paint_after_children` so z interleaves with children (native hosts call them back-to-back, so child-relative z is xpl-only).

## Interactive behaviors

A **behavior** is `NEUI_ASSET_KIND_BEHAVIOR` (`3`) - a mutable list of input handlers for a CUSTOMDRAW widget (declarative *input target*, parallel to compound's *visual*; a widget can have both). Mouse / key / wheel events run the handler list; the matching handler mutates a named float attr in the `AttrBag`; companion compound bindings re-render.

**Handler kinds**: `DRAG_VERTICAL`, `DRAG_HORIZONTAL`, `DRAG_ROTATIONAL`, `DRAG_BIAXIAL`, `WHEEL`, `KEY_STEP`, `CLICK_TOGGLE`, `CLICK_CYCLE`, `CLICK_SELECT`, `CONTEXT_RESET`, `DRAG_SOURCE`.

**API** (`include/neui/d/behavior.h`, `NEUI_API_BEHAVIOR`): `add_handler(kind)`, `remove_handler`, `clear`, typed `set_int`/`set_float`/`set_string`. Props - **common**: `target` (default `neui.param.value`), `target_default` (CONTEXT_RESET), `min`/`max`, `step`/`coarse`, `snap_attr` (default `neui.attr.steps`), `fine_modifier`/`fine_scale` (default 0.2), `cursor` (no-op v1); **drag**: `sweep` (200 px), `sweep_y` (BIAXIAL), `deadzone` (rotational, 4 px); **cycle**: `wrap`; **click-select**: `selected_attr` (int attr the click mirrors the on/off state into, 1 = selected / 0 = not; default `neui.attr.selected` = the key the compound `show_when` SELECTED axis reads; `""` = skip the mirror, plain toggle); **drag-source**: `threshold_px` (default 4), `allowed_actions` (bitmask, default `COPY | MOVE`), `drag_data_key` (attr key holding the `neui_data_item_t.id`), `drag_preview_key` (attr key holding the preview-image asset id; 0/unset = OS default visual), `drag_hot_x` / `drag_hot_y` (hot-spot on the preview, logical px from top-left, -1 = centre), `result_attr` (attr key the runtime writes as int with the negotiated `NEUI_DND_ACTION_*` after `begin_drag` returns; `NONE`/0 on cancel; fires `ATTR_CHANGED` + invalidate every drag completion regardless of value change; empty/unset = drop the action); **hit region**: `anchor_parent`/`anchor_self`/`offset_x`/`offset_y`/`width`/`height` (compound 9-pt anchor, defaults whole widget).

**Attachment**: `widgets->set_asset` kind-routes - BEHAVIOR → `WidgetData::behavior_asset`, COMPOUND → `compound_asset` (independent slots). **Dispatch**: hosts feed mouse / key / wheel into `behavior_dispatch_mouse` / `_key` (`behavior_runtime.h`) after the client's `onevent` returned false; a `BehaviorDispatchCtx` of host callbacks (`invalidate` / `emit_attr_changed` / `popup_menu` / `begin_drag`) keeps it platform-free. Wheel dispatch multiplies by `|delta|` (one notch = `step * lines_per_notch`). `NEUI_EVENT_ATTR_CHANGED` fires on user-driven writes; programmatic `attrs->set_*` stays silent. `DRAG_SOURCE` arms on MOUSE_BUTTON_DOWN inside its hit region; once the cursor crosses `threshold_px`, the runtime clears its drag state and fires `ctx.begin_drag(item, allowed_actions)` (blocking until the OS drag loop ends). The data item is resolved from the widget's AttrBag at `drag_data_key` (an int holding a `neui_data_item_t.id` the client built via `clipboard->create_item` before mouse-down).

## Declarative component format

A **component** is `NEUI_ASSET_KIND_COMPONENT` (`8`) - a reusable, JSON-authored definition of a composited control (knob, fader, ...) that bundles a COMPOUND (visual) + a BEHAVIOR (input) + a default-attr template + a param manifest + a default size. Load once, instantiate many; the compound + behavior are shared across every instance (shape shared, AttrBag per-widget). It replaces ~45 lines of imperative `add_layer`/`bind`/`add_handler` with one `create_component_from_file` + one `create_from_component` per instance. A *component* bundles a *compound* + a *behavior* - distinct kinds; don't confuse them. Parsed by the in-host `neui::mujson` (JSON-like: bare keys, trailing comma, `//` + `/* */` comments). Design rationale: `docs/design-notes.md`.

**Public API** (vtable-appended, no new `get_interface` entry). On `neui_asset_api_t` (`include/neui/d/assets.h`): `create_component_from_string(json,len,env)` / `create_component_from_file(path,env)` → a COMPONENT `neui_asset_t` (owns its compound+behavior+path-loaded layer assets; `destroy` releases them; `get_kind`→COMPONENT, `get_size`→default size); `component_param_count` / `component_param_at` (the `params` manifest); `serialize_component(component,out,cap,indent)` → re-emit the document (designer round-trip; minimal-diff, structure only, no per-instance values - asset layers serialize back by name). On `neui_widget_api_t` (`include/neui/d/widgets.h`): `create_from_component(parent,asset,x,y,w,h)` (create CUSTOMDRAW + attach compound+behavior + stamp defaults; `w/h<=0` = component default size). `set_asset` is also COMPONENT-aware (attach-to-existing CUSTOMDRAW: both slots + stamp). Per-instance values via the normal attr API. Types `neui_component_env_t` (base_dir + `resolve_asset` callback for injected/in-memory handles, consulted before path mode) + `neui_component_param_t` live in `assets.h` (avoids a circular include); `include/neui/d/component.h` is the doc umbrella + full JSON schema.

**Implementation**: host-side, not a client helper - the parser lives in the core lib, so parse+materialize run inside the host. The host-agnostic walker `hosts/shared/component_loader.h::build_component` drives the public compound/behavior/asset api vtables (handed in by each host); `serialize_component` introspects the built `CompoundAsset`/`BehaviorAsset` back to a `mujson::object_t`. The COMPONENT store entry (`hosts/shared/asset_store.h` `AssetEntry::comp_*` + `allocate_component`) owns the sub-assets + round-trip metadata (name, assets map, handle→name). Per-host glue (the 5 asset thunks + `create_from_component` + the COMPONENT branch in `set_asset` + COMPONENT case in `get_size`) is wired in all three hosts (`hosts/{crossplatform,win32}/widgets.cpp`, `hosts/macos/widgets.mm`). Every JSON field maps 1:1 onto an existing compound-layer / behavior-handler prop; `as_num` accepts both int and double arms, colors accept `#AARRGGBB` or a bare int. Verify: `tests/test_component_loader.cpp` (Tier-1, fake api vtables - load + serialize round-trip + minimal-diff) and `examples/component_knob_example.cpp` → `neui_component_knob_example` (loads `components/knob.json`, 4 knobs via both instantiate paths, an injected SURFACE pointer, + a serialize dump). **Note: `AssetEntry` grew with the `comp_*` fields - a full rebuild is required (incremental builds with stale objects compiled against the old struct size corrupt the entry).**
